# [세션] 2026-08-09 air-cashflow 중복 세션 복구 + 5단계 방향 확정

**프로젝트/주제**: Air Cashflow(EY Project Air 2 엑셀 자동화) 진행 점검, 세션 중복 작업 복구,
의뢰 커스터마이징 3종의 실현 가능성 실측, 5단계(편집 UI) 방향 결정.

## 결정 사항

- **5단계는 "값 편집 먼저", 방식은 A(일괄 조작).** "리스료 전체 x0.9", "트랜치 전체 +1%p"
  처럼 대상 + 조작을 입력하면 한 번에 적용한다. 엑셀식 표 직접 편집(칸 단위)은 다음 오더.
  이유: 의뢰 문장이 그대로 화면 조작이 되고, 20칸을 손으로 고치게 하면 아무도 안 쓴다.
- 기체 제외(의뢰 ①)는 값 편집을 끝낸 뒤 별도 과제로 분리.
- 편집은 이 앱의 첫 쓰기 경로이므로 **설계 문서 선행**. GUARDRAILS §7 이 "편집 UI"를
  "이 앱에 없는 것" 첫 항목으로 두고 아키텍트 선행을 요구한다. 서브에이전트를 띄우지 않고
  본 세션(다음 세션)이 설계 문서를 직접 쓰고 보스 승인을 받는 방식으로 계약을 지킨다.

### 4. 의뢰 커스터마이징 3종 실측 (핵심)

원본 DB 복사본에 fork 를 떠서 실제로 돌려 답을 냈다(스크래치 `probe_custom.py`,
`probe_drop.py`). 말로 추정하지 않았다.

| 의뢰 | 결과 | 근거 |
|---|---|---|
| 리스료 10% 삭감 | **됨 (코드 0줄)** | IRR Equity 10.77%→5.58%, PV FCFF 1,027M→981M, LTV 67.8%→71.0% |
| 이자율 1%p 인상 | **됨 (코드 0줄)** | IRR Equity 10.77%→8.65%, IRR S-Note 4.61%→5.65%(+1.04%p) |
| 기체 2대 제외 | **막힘** | `metrics.py:750` `IndexError` |

- ②③이 되는 이유: `aircraft.lease_rate`(20행)·`tranche.coupon`(A 0.043/B 0.0575)이
  이미 DB 행이고 엔진이 `build(inp=)` 로 주입받는다. 엔진 0줄, 스키마 0줄.
  **없는 것은 편집 경로뿐이다.** `dbctl set` 은 `param`(스칼라 48개) 전용이라 기체·트랜치를
  못 건드리고, 웹 API 에는 편집 엔드포인트가 아예 없다.
- ①의 벽은 두 겹: (얕음) 연쇄 삭제. msn 열을 가진 8개 테이블(aircraft, msn_param,

  함께 지우면 `inputs_from_db` 는 18대로 통과하고 M0~M6 도 다 돈다. (깊음) 집계층 —
  `metrics.py` 가 분기 시트 167~186행을 기체 20대 고정 슬롯(`for ofs in range(20)`)으로
  깔았다. 엔진 전면 재설계가 아니라 국소 수정 + 출력 형상 결정.
- ①에 딸린 문제 둘: **18대짜리 골든이 없어 검증 기준이 사라진다**(항등 테스트로 대체 필요),
  기체를 빼도 부채(A 603M + B 106M)·에쿼티는 20대 기준 그대로여서 **의뢰인에게 물어야 할

- 연쇄 삭제 전 단계에서는 `DatasetIncomplete`(maint_monthly 8440행 / 기대 7596)로 거부됐다.
  3단계 정합성 검사가 제 역할을 했다(조용히 틀리지 않았다).

  이 이미 있다), `editable=0`(수식 유래 94개)은 배지만 붙이고 편집은 허용(§13-1 결정),
  편집 이력은 dataset 세대로 남긴다.
- A(일괄 조작)의 설계 쟁점: 조작 종류(배수 / 증감 / 값 지정), 대상 선택 단위
  (기체 전체 / 특정 기체 / 트랜치 / 스칼라), 적용 결과를 새 dataset 이름으로 남기는 방식,
  그리고 "무엇을 얼마나 바꿨는지" 를 run 결과에서 되짚는 표시.

  동시 실행 금지. `tmp_path` 금지(이 PC 의 `%TEMP%\pytest-of-USER` 쓰기 권한 없음).
  `api/` 에서 `Depends` 로 sqlite 연결 주입 금지.
- 실측 스크립트는 스크래치패드에 있다(세션 종료 시 사라짐). 필요하면 같은 방식으로
  다시 만든다: 운영 DB 복사 → `AIRCF_DB` 지정 → `fork_dataset` → SQL 편집 →
