# [세션] 2026-08-06 아호비 배포 신원과 릴리스 관문

**프로젝트/주제**: 아호비 스튜디오 "개발한 게 배포에 반영 안 됨 → 수정 무한 반복"의
근본 원인 진단과 1층(빌드 스탬프)·3층(릴리스 관문 G1/G2/G5) 구현.

## 진단 결과 (이 세션의 출발점)

루프의 원인은 개별 버그가 아니라 **관측 불가**였다. 가진 신원이 `VERSION` 의
`x.y.z` 세 자리뿐이라 "지금 도는 0.7.3 안에 어제 수정이 들어있나"에 답할 수단이
육안뿐이었다. 진단이 불가능하니 추측으로 고치고, 추측이라 또 틀렸다.

찾은 누수 구멍 6개: 수동 동봉 화이트리스트(`bundle_payload.py`), 수동 `?v=`
캐시버스터, git 검사 없는 릴리스, 신원 부재, uvicorn 무reload(프런트는 즉시
반영/백엔드는 재시작 전까지 미반영), 두 스택 동시 구동 + 24h 전파 지연.

처방은 4층. **1층 신원 → 2층 수동 목록 제거 → 3층 릴리스 관문 → 4층 전파 가시화.**

## 결정 사항

- **1층부터.** 나머지를 먼저 하면 사고 빈도는 줄어도 진단 불가는 그대로다.
- **3층 관문은 "작업트리 청결"이 아니라 payload 한정.** 뭉뚱그린 검사는 안전한
  릴리스까지 막아 거짓 경보를 낳고, 우회 습관이 생겨 관문이 스스로 죽는다.
  (초안 폐기. 문서 §8-1 에 폐기 이유를 남김.)
- **G1과 G2는 서로를 대신 못 한다.** G1은 시작 시점, G2는 빌드 구간만 본다.
- **태그는 HEAD 가 아니라 스탬프의 커밋에**, 이미 있으면 옮기지 않고, 푸시는 사람이.
- 구조 변경이라 **문서 먼저, 끊지 않고 바로 구현.** (여러 세션이 이 저장소의
  문서를 읽고 쓰므로 잘못된 §8이 남아 있으면 다음 세션이 폐기안을 구현한다.)

## 사고 기록 (되풀이 금지)

- **0.7.4 가 감시자 수정이 빠진 채 나갔다.** 빌드 시작 시점엔 payload 가
  깨끗했는데 빌드가 도는 동안 다른 세션이 `client/watchdog.py` 를 고쳤다.
  0.7.5 로 다시 내보냈다. → G2 가 이 유형을 막는다.
- **한글 릴리스 노트가 뭉개진 채 게시됐다**(`"?대? 媛쒖꽑 ..."`). PowerShell 5.1이
  비ASCII 인자를 ANSI 코드페이지로 인코딩해 되돌릴 수 없게 깨뜨린다. 실패가 아니라
  성공으로 끝나서 아무도 몰랐다. `--skip-build` 재게시로 수습(sha256 동일 확인).
  같은 함정에 커밋 메시지로 한 번 더 걸렸다 → `git commit -F` 로 해결.
- **`dirty_paths` 가 통째로 미추적인 폴더를 `combine/` 하나로 접어** 보고해
  payload 판정이 어긋났다. `--untracked-files=all` 로 해결(스모크 13-7 이 발견).
