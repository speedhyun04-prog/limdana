# [세션] 2026-08-02 스튜디오 AI 생성 멈춤 기능

- **날짜**: 2026-08-02
- **프로젝트/주제**: 아호비 웹 스튜디오, AI 응답 생성 멈춤(클로드 코드식) + 생성 중 채팅 입력

## 결정 사항
- 멈춤 UX는 클로드 코드와 동일하게: 생성 중 전송 버튼(↑)이 멈춤 버튼(■)으로 변신, 부분 답변은 유실 없이 저장.
- 채팅으로도 멈춤: "멈춰·그만·중지·정지·스톱·취소·stop" 계열 한 마디(통짜 일치)만 멈춤 명령, 긴 문장 속 포함은 무시.
- 생성 중 친 일반 메시지는 무시하지 않고 대기열에 쌓아 턴 종료 후 자동 전송. 단 사용자가 멈춘 턴 뒤나 입력창에 초안이 있으면 자동 전송 금지(입력창에 되돌림).

## 진행 상황 (완료)
- 서버: `/api/chat`에 턴 id(turn) 등록제 + `POST /api/chat/stop` 신설(web/server.py, `_CHAT_STOPS` 레지스트리, 소유자만 멈춤 가능, gen() finally에서 이탈 시에도 정리). 부분 답변은 기존 done 경로로 저장.
- 두뇌 4종 모두 중단 지원: brain.py(클로드)와 local_brain.py는 기존 should_stop 물려줌, gpt_brain.py·codex_brain.py에 should_stop 신규 추가.
- **핵심 픽스 1(brain.py)**: async for 안 should_stop 검사는 다음 SDK 메시지가 와야 돌아 도구 실행 중엔 안 멈췄음 → `_attempt`에 0.25초 감시자(`_stop_watch`)를 넣어 신호 즉시 CLI 자식 트리 kill, 그로 인한 SDK 오류는 "멈춤이면 정상 종료"로 삼킴. codex_brain에도 같은 감시자 스레드.
- **핵심 픽스 2(plus.js)**: 전송 후킹 래퍼(hookSend)가 `if (streaming) return`으로 생성 중 모든 전송 호출을 삼켜 "작업중 채팅 무반응"의 진짜 원인이었음 → 생성 중엔 훅 없이 원본 send(멈춤/대기열 분기)로 위임.
- 프론트(chat.js): stopTurn(3초 무응답 시 AbortController 폴백), isStopPhrase, queuedMsgs 대기열, 답 나오기 전 멈춘 빈 말풍선엔 "생성을 멈췄습니다" 표시. app.css에 #btnSend.is-stop(시큐어 변형 포함).
- 검증: 도구 작업 중 ■ 클릭 후 0.996초 중단, 부분 답변 대화 파일 저장, 죽인 PID 소멸, 짤림 감사 0건, 대기열 자동 전송, "멈춰" 채팅 멈춤 모두 브라우저 실검증 통과. 테스트 대화 4건은 sessions/에서 삭제함.
- 운영 서버(8765, pythonw run_server.pyw)는 두 차례 재시작해 반영 완료. 이후 프론트만 바뀌어 추가 재시작 불필요.
