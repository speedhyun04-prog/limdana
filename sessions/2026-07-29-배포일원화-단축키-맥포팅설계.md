# [세션] 2026-07-29 아호비 배포 일원화 · 단축키 복구 · 0.5.0 릴리스 · 맥 포팅 설계

**프로젝트/주제**: 사원 배포판에서 기능이 안 되는 원인 진단 → 조치 → 0.5.0 게시 → 맥 포팅 설계

## 결정 사항

- **단축키 소유권을 개발기 런처에서 트레이 에이전트 본체로 옮긴다.** 런처를 exe 에 동봉해
  프로세스를 하나 더 띄우는 대신, 이미 상주 중인 에이전트가 소유한다(프로세스 증가 없음).
- **버전 bump 는 minor(0.4.9 → 0.5.0).** 단축키 신규 + 메일·방그룹·매뉴얼 동시 포함.
- **커밋은 세션별로 분리.** 타 세션 오후 작업물과 내 작업을 한 커밋에 섞지 않는다.
- **쥰이(jyuni)를 admin 으로 승격.** 사원 AI 사용료 정책은 아직 미결(아래 "남은 결정").
- **맥 포팅: 소스는 한 벌, 산출물은 완전 분리.** 소스를 두 벌로 가르면 기능 추가 때마다
  한쪽을 빠뜨린다(이번 단축키 사고가 정확히 그 유형).
- **맥 대상은 Apple Silicon(arm64) 단일.** 보스 장비가 M칩.

## 진행 상황

### 완료

**1. 배포 일원화 진단 — 사원 PC 기능 누락의 진짜 원인 3가지**

- **단축키가 설치판에 아예 없었다.** RegisterHotKey 를 부르는 곳은 개발기 런처
  (`ahovye_launcher.pyw`) 하나뿐인데, 이 파일이 `installer/ahovye.spec` datas 에도
  `deploy_entry.py` 분기에도 없었다. 배포판 코드의 핫키 등록은 **0줄**. 그런데
  index.html 툴팁 3곳·settings.js·intro.html·install.ps1 은 전부 된다고 안내.
  버그가 아니라 **산출물 누락**. 보스 PC 만 소스+런처라 잘 됐다.
- **자동 업데이트가 조용히 끊긴다.** 업데이터는 `--agent` 트레이 프로세스 안에서만
  돌고, 적용은 에이전트 재기동 시에만. 설치 시 "자동 실행" 체크를 껐거나 PC 를 안 끄면
  영영 안 올라간다. 확인 주기 24h, 모든 실패(이름 해석·타임아웃·설치 실패)가 로그
  한 줄로 조용. 서버 주소 `desktop-1o0eii1.local` 은 LAN/Tailscale/IPv6 4개 주소로
  해석돼 엉뚱한 주소를 먼저 잡을 여지. `updater.py:252` 러너가 성공/실패 무관하게
  설치판+.ok 를 지워 설치 실패 시 재시도 없음(문서 §4 에 이미 "의도와 다름"으로 기록).
- **배포 경로 이원화.** `installer/install.ps1`(보스 PC 경로 하드코딩, 소스 실행, 런처
  등록, Ollama 설치)과 Inno 설치판이 공존. 런처 계열은 단축키 되고 업데이트 안 되며
  설치판 계열은 반대.

**2. 관리자 버전 현황판 신설** — `GET /api/admin/agents` API 는 있는데 화면이 없어
보스가 열어볼 데가 없었다. `web/admin.html` 에 패널 추가(서버 최신 버전은
`/static/dl/latest.json` 을 직접 읽어 비교 — 화면에 버전 상수를 박지 않음).
짤림 감사 1280px·420px 결과 0.

**3. 전역 단축키 에이전트 이전 + 입력창 위 아호비 (커밋 80ce9b0)**

- `client/hotkey.py` 신규 — Win32 RegisterHotKey + **QAbstractNativeEventFilter**.
  에이전트가 Qt 앱이라 런처처럼 별도 메시지 루프를 안 돌린다. hWnd=None 핫키의
  WM_HOTKEY 가 스레드 큐로 와 Qt 필터에 잡히는 것을 **실제 키 주입으로 실증**.
- 키 배치는 런처와 동일(Alt+Space 코드모드 → ↑입력창 / ↓상주창(↓↓숨김) / ←→단계).
  명령 대상만 배포판에 맞게 교체: 입력창=오브 `/type`(꺼져 있으면 `--orb --type` 기동),
  창 단계=셸 가드 8767.
- **카드 위 아호비**: jarvis HUD 는 `addWidget(orb)` → `addWidget(card)` 구조인데
  §10 이식에서 이 조각만 빠져 있었다. 카드 폭이 이미 HUD 와 같아(468) 오브도 비례가
  아니라 **같은 172**. 패널이 열려 있는 동안 상주 오브를 숨겨 중복 방지.
- `installer/ahovye.spec` 에 `client/hotkey.py` 추가 — **누락이 원인이던 그 목록**.

**4. 0.5.0 릴리스 게시 (커밋 16c01d6)** — 6단계 전부 성공(Inno 압축 122초, 전체 3분).
144MB, sha256 25ff869c…. **Inno 압축 로그에서 `client/hotkey.py` 동봉을 눈으로 확인.**
가이드 HTML 3종 수동 갱신(release.py 가 안 건드림). 사내망 서빙 확인 완료.

**5. 맥 포팅 설계 (커밋 bdbd242)** — `docs/ARCHITECTURE_MAC.md`. 구현은 착수 전.

### 작업 중 잡은 실제 버그 3건

- **초기화 순서**: `orbface.installEventFilter(self)` 를 `self.input` 생성 **전에** 걸어
  위젯 생성 중 이벤트가 없는 속성을 건드려 orb 스모크 5개가 무더기로 깨졌다.
- **포그라운드 잠금**: 단축키로 열면 창은 떠도 **타이핑이 안 된다**. 핫키를 받는 건
  에이전트, 창을 띄우는 건 오브로 프로세스가 달라 Windows 가 막는다 →
  에이전트가 `AllowSetForegroundWindow(ASFW_ANY)` 로 권한을 넘기고 오브가
  `SetForegroundWindow` 로 받아 쓴다.
- **릴리스 순서 실수(내가 밟음)**: 빌드가 압축 중일 때 install.html 다운로드 링크를
  0.5.0 으로 먼저 바꿔서, exe 가 배포 폴더에 복사되기 전까지 깨진 링크 창이 생겼다.

### 남은 결정 (보스)

1. **사원 AI 사용료 방향** — 구독에는 API 키가 없다(구독=브라우저 OAuth, 키=console
   종량제). 세 선택지: ①회사 부담·서버 인증 공유(member 도 admin 처럼) ②사원 개인
   구독을 서버에 연결(CLAUDE_CONFIG_DIR 분리, 사원마다 서버에서 브라우저 로그인
   필요·토큰 만료·약관 확인) ③회사 명의 API 키를 사람별 발급. 현재 member 잔여 2명
   (얌모·김하린)은 여전히 키 화면을 본다.
2. **맥 단축키 조합** — ⌘+Space 는 Spotlight 예약. ⌥+Space 추천(윈도우와 같은 물리 자리).
3. **맥 코드 서명** — 없으면 Gatekeeper 가 막는다(윈도우 SmartScreen 보다 강경).
   Apple Developer $99/년.

### 남은 작업

- **사원 5명 내외에게 0.5.0 수동 재설치 안내** — 자동 업데이트가 안 도는 PC 는 이
  한 번이 있어야 순환이 깨지고, 그 뒤부터 `/admin` 현황판에 버전이 찬다.
  안내 시 **"윈도우 시작 시 자동 실행" 체크 필수**(꺼져 있으면 자동 업데이트 영영 안 됨).
- 맥 포팅 구현 1~7단계(설계 문서 §6 순서).

## 다음 세션에서 필요한 맥락

**맥 포팅을 시작하려면**: `docs/ARCHITECTURE_MAC.md` 를 읽고 §6 작업 순서대로.

updater_common/config/combine.common/agent.pyw — 플랫폼 분기를 흩뿌리기 전에 한 곳으로).
1~4단계는 윈도우 PC 에서 하되 **매 단계 윈도우 스모크로 회귀 확인**, 5단계부터 맥 필요.

```
python tests\test_orb_smoke.py          # orb 9항목

python /c/Users/USER/dev/scripts/pycheck.py <파일들>
```

- 보스 노트북은 개발기 런처가 Alt+Space 를 선점해 에이전트 등록이 **err=1409 로

  트리거 키만 몽키패치(예: Alt+F9)해서 검증.
- 오늘 오후 내내 **다른 세션이 방 그룹·메일 작업을 동시 진행**했다. 커밋 전 반드시

- 릴리스는 `python installer\release.py --bump minor --notes "..."`. 가이드 HTML
